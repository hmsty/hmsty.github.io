A Web3 Dev Environment

a local environment for reading, analyzing, monitoring and transacting on blockchains through Claude Code

A confession: My first BTC exposure came in the form of a wrapper on rolled-over futures (BITO). I later moved over to IBIT to avoid the roll costs inherent to a futures-based financial product. Neither is, really, owning bitcoin. This project began as my way of closing that instance of mental dissonance.

So I set up the real thing: a few dollars of USDC in a wallet I control, held on my own machine, and a way to use it. I ask Claude Code for things in plain English, from what a contract does to moving the money. Each transaction is signed on my Mac after I approve it with Touch ID, and there is no server.

how a transaction works

  1. Claude Code looks up what it needs, such as rates, risk and balances, then queues a proposal.
  2. The proposal is decoded from the raw transaction and checked against limits on chains, protocols, assets and size.
  3. I read it in my terminal and approve with Touch ID. Only then does the signing code run.

  ok   0x…
  ok   0x…

An approval in the terminal. Addresses and hashes are elided. The private key stays on this machine, and the server Claude Code talks to has no code path to it.

what it does

  • Reads the chain. Balances, rates, utilization and prices straight from the contracts on Base, Arbitrum and Optimism, plus market data from DefiLlama and Hyperliquid, which is read-only.
  • Explains it. Any contract (who controls it, whether it can be upgraded, what is privileged) or any transaction (what it did, which tokens moved, what it cost), in plain English.
  • Watches for changes. Upgrades, ownership changes and pauses on the contracts it depends on, stablecoin price moves, and new exploits.
  • Moves money. Deposits and withdrawals on Aave, Compound, Morpho and Fluid, USDC between chains through Circle's CCTP, and approvals and revocations.
  • Checks its own work. Open token approvals, transaction receipts, and wallet transfers as they land.
  • Keeps a record. An hourly history in a local database that I can query with SQL, with earnings estimated from receipts and exported as CSV.

what I learned

  • Exposure and ownership are different things. A fund or a futures product gives price exposure. Holding the asset myself adds custody and keys and removes the safety net: nobody can freeze or reverse a transaction, or recover a lost key. So most of the work went into making mistakes hard to make.
  • Where the money sits decides who carries the risk. At an exchange the balance is a ledger entry the company keeps. In a lending protocol it is a claim on a pool that borrowers draw from, so the risk moves to contract code, collateral and price feeds.
  • Yield is what borrowers pay, so it follows demand. Aave's USDC market on Base ran near 90% utilization, and the highest rates came with something attached, such as a small market or reward tokens.
  • Gas sets what is practical at small sizes. The day I checked, a deposit-sized transaction cost about 4 cents on Ethereum mainnet and under half a cent on Base. Layer 2s get cheap by batching transactions to Ethereum, and the trade is that leaving through the official bridge takes about a week.
  • Research is safe to hand to an AI. The last step isn't. The data is public, so an assistant can read and propose freely. The step that moves money can't be undone, so it stays with me.
